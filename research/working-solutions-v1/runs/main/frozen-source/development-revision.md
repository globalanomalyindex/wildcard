# One permitted calibration revision: limited public feedback

Decision after development-1, before development-2 or any main call. Author: christopher robin fiore.

The frozen first calibration completed all 48 logical calls with valid delivered responses. The direct condition passed 2,048/2,048 hidden traces across all eight tasks (mean 1.000), triggering the predefined >=.95 ceiling. Main acquisition is blocked. Matched and shuffled outside conditions each passed 1,979/2,048 traces (0.96630859375); these remain descriptive development observations and did not choose this revision.

The single revision reduces the observed public-example budget equally for D, R and X: retain the same four public fixtures and configurations, but show and check only the first four events of each trace. The complete target specification, task identities, generator, hidden-case allocation, reference/checker semantics, card bank/matcher, two-call budget, response limits, model configuration and inference rules remain unchanged. Programs still receive one current event at a time. Prefix fixtures are valid because later events cannot alter earlier required outputs.

This creates a limited-feedback setting: at most 16 observed event/output pairs per task rather than four long, regime-covering traces. It deliberately changes the benchmark's difficulty and scope, and is not an improvement demonstrated by the first experiment. Full fixture generators remain available for auditing; only the frozen public-material constructor applies the common prefix budget. Duplicate prefixes, when they occur, are not counted as independent observations.

Reason: the direct system already solved the complete first development sample, so the initial setting had no remaining benefit to detect there. Reducing comprehensive public feedback is a global difficulty revision based on D alone. The four-event cutoff is fixed for every task and condition before second-round generation; no task-specific cutoff search or outside-arm optimization is permitted.

Development-2 uses a fresh committed seed and the same eight development task contracts. It is a second calibration round, not an independent replication or a confirmatory test of an outside benefit. The original source snapshot and complete development-1 data remain immutable. The frozen analysis entry point reproduces that older version after this prospective source change.

The same readiness rule applies: D mean must be strictly between .10 and .95. If development-2 is still at floor/ceiling, halt the main test and publish the calibrated system and limitations. Do not relax the gate, run a third calibration, or expand samples to obtain a preferred conclusion.
