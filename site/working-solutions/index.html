  1. 01

    borrow a relation

    Use an outside source where its assumptions fit, or derive a rule directly from the task.

  2. 02

    make it checkable

    Write an input condition and a behavioral rule. Correct examples must pass; at least one wrong output must fail.

  3. 03

    repair once

    Every condition receives the same public execution checks and one chance to return its final program.

  4. 04

    open the withheld tests

    Freeze every final program first. Then reveal the test seed and evaluate unseen legal inputs.

A rule that passes a few examples is useful evidence of consistency, not a proof. The direct comparator gets the same rule fields, checks and repair opportunity.

what the work can claim.
a controlled question
Matched outside information is compared with direct derivation and an intact shuffled source. Calls and public feedback are matched; actual token use is recorded.
a bounded benchmark
Authored software contracts and generated cases test specific behavior. The task is the analysis unit. More test cases do not become more independent research samples.
an inspectable method
Analogy prompting, executable contracts and repair all have prior art. The contribution is this comparison, its conditional transfer representation and its complete evidence.
