## angles
- genomes accumulate genes from many lineages but express them conditionally by cell type, not everywhere at once -> your nav tries to express all 13 items for everyone but you have 60,000 separate accounts not one organism -> compute what renders per account from actual usage, making this a data/personalization problem not a menu-redesign problem
- governing 60,000 jurisdictions with one constitution while past side-treaties become permanent global law -> federalist systems keep a thin universal core and devolve everything else to state/local -> version nav per account like an API; legacy accounts keep their current nav indefinitely unless they choose to migrate; new signups get minimal default; bloat stops compounding
- cities don't demolish neighborhoods to fix traffic; they separate arterial infrastructure (highways, fast, minimal) from local streets (numerous, specific, still accessible) -> "can't find anything" is a wayfinding problem not an inventory problem; 13 things can feel like 4 with a clear highway for the common case -> build a command palette/universal search as the arterial road so most navigation never touches the top menu; also conduct a desire-path study of where people click when lost
- high-volume restaurants carry huge menus but use layout, sectioning, chef's picks to make 200 items feel curated on first glance -> this is a presentation/hierarchy failure not an inventory failure; the first page doesn't need to show everything with equal weight -> separate "exists and is reachable" from "is default top-level"; give each account a small number of default items by usage pattern with the rest under "More"; this changes prominence not existence
