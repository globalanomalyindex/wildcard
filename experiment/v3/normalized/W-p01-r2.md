## angles
- Continuous order decay of `pg_stats.correlation` crosses a threshold causing discrete planner flip (index → sequential scan), appearing as sudden 40x regression -> Slow decay hitting a discrete decision boundary explains the 200ms-to-8s creep better than gradual degradation -> Run `SELECT correlation FROM pg_stats WHERE tablename='events' AND attname='<time_column>';` and add BRIN index if below 1.0 to exploit physical/time correlation
- Single large crystal requires repair-carrying defects to migrate far to reach damage; fine-grained polycrystal anneals orders of magnitude faster with same mass because each repair's search domain is smaller -> Autovacuum on 600GB table is single-crystal case that structurally cannot finish inside business-hours window -> Partition events by month and run VACUUM FREEZE on cold partitions; frozen partitions drop from autovacuum maintenance, shrinking surface to current and prior partition
- One deliberately-placed stacking fault (single layer out of normal sequence) changes bulk crystal property everywhere without re-engineering atoms -> ORM SQL can't be hand-tuned call-by-call but one well-placed layer changes bulk behavior -> Build incrementally-maintained rollup table (hourly/daily pre-aggregates), repoint aggregate reads at it via renaming so ORM scans thousands instead of full table; eliminates multi-hour nightly recompute colliding with EU morning peak
