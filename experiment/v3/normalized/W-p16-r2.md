## angles
- an enterprise team's daily habit is trained on literal click location (4th item, top right, gear icon); a first-time self-serve user reads the nav cold, trying to parse what's grouped with what -> the thing enterprise muscle memory depends on (exact position) and the thing self-serve users are struggling with (how many things there are, how they're grouped) are separable — you can hold one fixed while changing the other -> segment nav rendering by usage habituation, not plan tier; accounts with daily touches get position locked permanently; new accounts see 13 destinations collapsed into roughly 5 labeled groups

- every nav item has one large account using it daily is read as proof nothing can be cut -> this only proves each item needs to stay reachable, not that each needs a separate top-level position; two things built at different times can still turn out to be the same destination in practice, used by the same workflows in the same sessions -> pull session logs and compute for every pair of the 13 nav items what fraction of sessions touch both within one task window; pairs with heavy overlap (>40%) become merge candidates — one item with sub-tabs, keeping all existing URLs and deep links alive

- settings tabs driving a quarter of tickets are treated as a "can't find the tab" problem, inviting rearrangement, which cost three enterprise escalations already -> how many steps from where a user is to where they need to be doesn't depend on any tab's position — a shortcut can shrink that distance to zero without touching the layout -> ship a global command-palette/jump-to-setting search indexing all 9 settings tabs and all 13 nav destinations — pure addition, zero repositioning, zero escalation risk
