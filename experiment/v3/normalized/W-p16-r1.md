## angles
- Sharpness-per-tooth doesn't measure bite-of-whole-chain; a sharp tooth underperforms if its depth gauge isn't lowered to match -> usage log is per-item sharpness check but structurally misses bloat, which is a whole-loop property -> track total friction directly (clicks or decision-points to first meaningful action), set explicit quarterly budget, use that as the removal criterion instead of per-item DAU

- Raker height is material-specific, not universal; depth gauge tuned for hardwood is over-aggressive for softwood -> enterprise workflows and first-pass self-serve are different materials running through the same nav bar -> give different defaults per account type instead of one global setting; curated 5-6 item default for new or small accounts, auto-expand to full set for enterprise profiles (by seat count or feature usage), nothing removed for accounts actually using items

- Touching one tooth's raker in isolation makes the whole loop chatter; fix requires a full pass across a batch done together -> last nav change was single-item spot-move and caused three escalations; not proof that nav changes are unsafe, but evidence that a lone touched tooth needs set-wide recalibration -> next change should be one bundled, pre-announced pass (collapse settings tabs, fold items into submenus), shipped together with advance notice to heavy users and an explicit rollback path
