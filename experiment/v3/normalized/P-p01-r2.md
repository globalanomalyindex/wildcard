## angles
- Events table is write-heavy log structure (Cassandra/RocksDB/time-series shape) -> 90-day queries scan mix of still-written and settled rows through same machinery -> partition by time (Postgres 13+) so only recent partitions touched by autovacuum; older partitions read-only/vacuum-freeze'd
- "Autovacuum falls behind" is same pattern as GC can't keep up; runtimes solved via generational collectors -> every row competes for same vacuum worker regardless of age -> time partitioning: young generation gets aggressive per-partition autovacuum, old generation needs none
- Finance never recomputes past; closed periods become permanent snapshots -> 90-day rollups recompute settled days 1-89 every query though they won't change -> materialized daily pre-aggregates for closed periods; join instead of scanning raw table
- Nightly batch collision with EU mirrors ops scheduling at fixed time not tracking actual trough -> assumes one quiet global moment; doesn't exist with distributed users -> spread reporting into smaller incremental work each region's trough can absorb
