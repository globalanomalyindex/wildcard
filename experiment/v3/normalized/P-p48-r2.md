## angles
- Six-day lease overlap treated as scheduling headache, but structurally identical to blue-green deploy (old and new environments simultaneous, zero-downtime cutover) -> exploit the overlap by doing riskiest transfers during the window when both environments live, treating "old apartment still works" as rollback option -> use six days to get ISP installed at new place while current internet backs up, sequence non-essentials first, last day for anything that breaks
- Modeled as "40 separate updates," but passport-in-transit and 40-accounts are one problem — information routing, not separate items -> instead of 40 point-to-point calls, insert relay in middle — USPS mail forwarding reroutes misdirected mail so accounts unreached aren't silently lost -> file forwarding first, converts "40 urgent updates" into "40 updates on whatever timeline"
- "Forty accounts" carried as undifferentiated mass, causes paralysis -> triage sorts by what happens if this one waits, not by quantity — passport time-critical, voter registration no consequence for weeks, car registration has grace period, utilities date-locked -> sort into failure-mode buckets, shrinks urgent-during-business-hours pile from 40 to handful
- Constraint is synchronous tasks (phone calls) colliding with 9-6 job, not task volume — scheduling collision -> pit crews solve "everything in narrow window with one person" by pre-assigning who touches what, not sequential real-time from one person -> look for asynchronous options (chat, portal, callback) before assuming live call, consider whether new building leasing office can proxy ISP install
