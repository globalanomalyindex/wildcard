## angles
- F = mv²/r, the cheap lever is usually the radius -> events table growth is the "speed," table sweep size is the "radius" -> range-partition events table by time (monthly) to bound radius to constant handful of partitions per query, with partition pruning at planner level
- Centripetal force must be supplied continuously or the system reverts to its default shape -> autovacuum's role in visibility map; when it lags, stale visibility bits force index-only scans to fetch from heap row-by-row -> check EXPLAIN ANALYZE for Heap Fetches count; use per-table autovacuum_vacuum_insert_scale_factor override to aim force where churn occurs
- An orbit that looks calm from one reference frame looks like it's flying apart when the center itself moves -> nightly reporting job was scheduled around an implicit quiet window that no longer exists as usage globalized -> replace heavy nightly batch with incrementally refreshed materialized view or rollup table, eliminating the single scheduled spike
