## angles
- One huge append-only stream read in recent time-windows -> structurally same problem as Kafka, logrotate, LSM-tree storage -> partition by time range; treat old partitions as closed segments that autovacuum can ignore
- Autovacuum lag in append-heavy table -> garbage-collector generational problem (most objects die young) -> tune insert-driven autovacuum triggers for continuous freezing in small bites instead of catch-up passes
- Can't take downtime or modify app code -> same constraint online schema-change tools solved -> shadow table cutover pattern: build partitioned replacement table alongside, backfill and replicate live, atomic rename in maintenance window
- EU-morning/nightly-job collision -> demand-response peak-load management problem -> logical replication read replica dedicated to reporting; shifts OLTP primary's burden structurally rather than tuning individual queries
