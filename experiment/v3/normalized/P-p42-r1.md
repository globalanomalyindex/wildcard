## angles
- Coupling through a general-purpose computer enables storage corruption; critical path lacks independent control -> fail-operational design decouples core functionality -> wire the switch for direct local control to bulbs or hub, retaining basic operation when the system fails
- SD card corruption arrives as surprise ambush rather than managed event -> chaos engineering treats expected failure as something to rehearse deliberately on schedule -> intentionally trigger the failure mode with a backup strategy in place and time the recovery procedure
- Flow knowledge lives in memory and degrades over time without external reference -> inherited legacy code requires annotation rather than re-derivation from scratch -> spend time adding descriptive comment nodes opportunistically to flows during regular maintenance
- The system exists in memory and stale disk images rather than in reproducible definitions -> infrastructure engineering shifts from pets (individual nursed systems) to cattle (disposable, regenerable instances) -> version control flow JSON and configs in git with automatic sync; treat corrupted cards as fresh-flash-plus-git-pull operations
