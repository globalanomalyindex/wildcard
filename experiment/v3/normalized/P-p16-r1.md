## angles
- Concentrated benefits/diffuse costs (Olson): organized minorities defend concrete wins while disorganized majorities silently churn -> grandfather clause approach: simplified nav for new/low-usage accounts, existing power users keep current navigation untouched
- Collection vs. catalog separation (library/airport systems): "bloated" complaint targets default view not inventory -> build query layer (search, personalization, role-based defaults) separate from full nav shelf
- Engagement options ≠ conversion options (Iyengar jam study, Cheesecake Factory): two populations experiencing two different problems (bloat complaints cluster in early users vs. daily active enterprise usage) -> segment verbatims by tenure and account size; if complaint is <90 days, it's onboarding not info-architecture
- Keystone-species triage: each nav item has minimal devoted users but not all are load-bearing -> score items on breadth vs. depth, fold broad-and-shallow into "more" menu or search-only access, leave narrow-and-deep in place or toggle by role/account-type
