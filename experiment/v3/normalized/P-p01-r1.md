## angles
- Append-only writes with slow reads and no ability to modify read path -> exactly what event-sourcing solves by separating write and read models -> stream events table into separate aggregation store via CDC (Debezium, logical replication), so nightly jobs and EU morning peak don't contend over the same rows

- Two-thirds of a 900GB events table is immutable history -> resembles geological strata or library archive systems with hot active layers and inert sediment -> use time-based partitioning (monthly); autovacuum and indexes operate on the hot slice only; older partitions compress or move to cheaper storage untouched

- Fixed Sunday-night maintenance windows collide with EU morning traffic -> same pattern electrical grids used before dynamic pricing: single large batch instead of continuous adjustment -> tune `autovacuum_vacuum_cost_limit` and `cost_delay` for continuous background trickle during business hours rather than a big window that inevitably conflicts

- 200ms–8s creep on 90-day rolling aggregates -> classic symptom of full recomputation when the answer could be maintained instead (like spreadsheet autorecalc or Postgres continuous aggregates) -> maintain a rolling pre-aggregated summary updated incrementally as events land, turning O(90-day scan) into O(new rows since last refresh); no ORM changes needed
