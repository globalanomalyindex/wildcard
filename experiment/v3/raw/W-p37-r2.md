Drawing on a specialist from outside seafood logistics entirely: someone who works the temporal spine of a toponymic gazetteer — the discipline that decides not just what a place is called, but exactly which time-window each name was authoritative for, across every chart, survey, and local variant that ever referenced it. The failure that specialist loses sleep over is the orphaned or recycled label: a name nobody bound back to one persistent record, so years later no one can tell which name applied when, or worse, the same label gets quietly reused for two different things.

A few things that surfaced from that angle, worth what they're worth:

**The crosswalk problem**
In that world, a name is only as good as the moment it's bound to one persistent ID — every other document that mentions it (an old chart, a colonial record, a local's spoken variant) has to resolve back to that single ID through a lookup table, or it's just noise nobody can chase. Your invoices, delivery manifests, box labels, and whatever a chef says over the phone are effectively four different naming systems for the same physical lot — which is why a rejection call turns into an afternoon of paper-digging: the crosswalk is getting built by hand, after the fact, instead of once, up front. Concrete move: stamp one lot ID (something like supplier code + landing date + sequence, e.g. `OYST-B-0814-03`) on the pallet the moment it clears the dock, print it on the box label, and carry that same field on the invoice and delivery manifest. A chef reading a box out loud then hands you the answer directly instead of a starting point for a search.

**Interval, not flag**
A single timestamp rarely settles anything in that field — the question that gets asked later is almost always "what applied during this window," so every entry carries a start and an end, not one point in time. Right now your three excursions this month are visible only as a single yes/no (did it cross 40), when the more useful record, both for you and the inspector, is an interval one: how long, and at what point in the morning sort, did each lot sit above threshold. Concrete move: log two timestamps and two temp readings per batch at the dock — one the moment it hits the receiving floor, one the moment it leaves for cooler or van. That start/end pair is the actual record the inspector is asking for, and a month of them stacked up will show whether the excursions cluster at the same stage of the sort (last batch through, same hour) rather than looking random.

**Let the timestamp do the judging**
In that archive, name-currency is never left to someone eyeballing it — a stamped date does the judging, automatically, so nothing gets misjudged by memory. Applied here: once the lot ID above carries a landing timestamp, let that timestamp trigger the day-two markdown itself — anything past the cutoff auto-flags and routes to the fish-market channel — rather than relying on someone in the cooler to judge freshness by eye. Same threshold you're already using, just running off the stamp instead of a glance.

All three lean on the same first move (a lot ID stamped at the dock), so it's really one piece of infrastructure with three payoffs — traceability, the temperature record, and the markdown trigger.
