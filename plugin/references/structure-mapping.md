# Map relations, then test the proposal

Comparing relations can be useful when a cue and a problem do not share subject matter. A matching word is not evidence of a matching mechanism. A relation can also suggest a question or technique without proving that the two systems are equivalent.

Keep the donor fact, transfer hypothesis and target check distinct. Do not call an analogy a scientific finding or a genuine isomorphism merely because it sounds coherent. Removability tests actionability, not donor truth or target correctness.

## A deliberately hypothetical example

Imagine two toy systems defined by this brief: each releases a batch of queued work when a shared timer fires. A simultaneous burst exceeds the stated processing limit. The donor story suggests a scheduling question for the target: could spreading release times reduce the peak?

The proposed target move is to compare the current release schedule with a staggered schedule under the same recorded workload, measuring peak arrivals and completion delay. That proposal is supported by the toy setup's explicit assumptions. It is not evidence about predator-prey dynamics, a real queue's bottleneck, or a proven performance improvement. If the actual target has no such batching behavior, the analogy does not supply that missing fact.

By contrast, “your code has cells and biology has cells” identifies only a shared word. It supplies no relation or testable action.

## Checks before offering a strand

1. **Donor:** what relation is supported, and what is assumed or uncertain? Verify technical claims that materially justify the move.
2. **Target:** which actual parts of the frozen brief participate in the proposed relation? Name where the mapping stops.
3. **Removal:** with the donor explanation deleted, does a relevant executable action remain?
4. **Validation:** how could the user check the action against their constraints? A test proposal is not a positive test result.

Release a strand if its only strength is rhetorical similarity. If one bounded refinement does not clarify it, drop it. Do not invent a number, file, constraint or resource to pass the checks. Suggested thresholds must be explicitly proposed and calibrated, not presented as requirements already supplied by the user.

## Offer the move

Use three short beats: a grounded noticing, a transfer hypothesis with its limit, then an optional concrete action and observable check. Anchor it in at least two actual particulars from the problem when available. Collapse any strands that propose the same action under different metaphors. One useful direction is enough; none is also an acceptable result.

Keep the user's goal intact. Add a possibility, rather than replace their question or label their existing method a failure. For example: “A second pass could check whether the existing reveal is prepared by an earlier concrete detail; compare the draft with and without that detail.” This is a proposal about the text, not a claim that a craft analogy diagnoses the writer.

If nothing withstands review, a concise response is sufficient: “This draw did not give me a defensible move for the brief. I would rather leave it here than force the connection.” Do not attach an unsupported fragment merely to soften abstention.
